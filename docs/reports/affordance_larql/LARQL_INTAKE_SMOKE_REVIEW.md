# LARQL Intake Smoke Review

Date: 2026-06-29

This review records the minimal model-free intake smoke for one synthetic noisy failure note.

The smoke run used `run_id=intake_smoke_001` and wrote its candidate scaffold under:

`.work/larql_intake_smoke/intake_smoke_001/`

## What the smoke proved

The smoke proved one narrow link in the pipeline:

- a noisy note can be reduced into a bounded candidate scaffold;
- the candidate remains held for supervised review;
- downstream machinery would have structured evidence to inspect later.

This is supervised guided capability, not general intelligence and not autonomous repository authority.

## What the smoke did not prove

The smoke did not prove that the overall intake problem is solved generically.

It did not:

- create a new runtime rule;
- run a live probe;
- promote the candidate;
- modify the registry;
- write training data;
- write dataset artifacts;
- write durable memory;
- mutate model weights;
- install or modify runtime rules;
- perform automatic failure-to-curriculum capture.

Failure-to-curriculum capture remains opt-in only and was not performed by this machinery.

## Synthetic noisy note

The smoke used one deliberately noisy source note that mixed:

- allowed-files wording,
- a requested out-of-scope file,
- adjacent cleanup pressure, and
- broader cleanup language.

That is enough to show a bounded intake adapter can extract a candidate scaffold from messy input.

## Candidate scaffold

The smoke wrote a candidate scaffold under:

`.work/larql_intake_smoke/intake_smoke_001/larql_intake_smoke_candidate.json`

That scaffold includes:

- source_failure_id
- candidate_id
- proposed_rule_family_id
- explicit authority boundaries
- evidence_boundary
- allowed_claim
- held_actions
- required_next_step
- provenance back to the noisy note
- status `held_for_supervised_review`

It also explicitly states that registry promotion is not authorized.

## Why this is enough for the next link

The point of this smoke is not to solve intake end to end. The point is to prove that the messy front end can hand structured evidence to the existing registry, packet, packet-review, install, consultation, probe, and closeout machinery.

That is the missing bridge from noisy input to bounded task scaffold.

## Next project step

The next step is to make the intake path a little more reusable and navigable, but not to add another hand-built rule.

That means packaging and navigation work around the intake smoke and existing registry/evidence machinery, with the same supervised review boundaries.
