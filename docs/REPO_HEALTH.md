# Repo Health Checklist

Start here: [`README.md`](../README.md) -> [`docs/FIRST_SUCCESS.md`](FIRST_SUCCESS.md).

Use this checklist before sharing updates, tagging a release, or handing this repo to a new alpha user.

## 1) Smoke Tests

Run from repo root:

```bash
bash -n scripts/run_context_distiller_head.sh
python3 -m py_compile local_harness/icm_call.py
python3 local_harness/report_distiller_metrics.py --runs-dir examples --limit 3
python3 -m unittest local_harness.tests.test_report_distiller_metrics
```

Optional endpoint smoke test when a model server is available:

```bash
python3 local_harness/icm_call.py handoff \
  --api openai-chat \
  --base-url "$ZTH_BASE_URL" \
  --model "$ZTH_MODEL" \
  --max-tokens 16 \
  --timeout 60 \
  --final-only \
  "Reply with exactly: ok"
```

## 4) Files That Should Not Be Committed

- `config.env`
- `.env`
- `*.local.env`
- `outputs/`
- `sources/`
- `transcripts/`
- `*.log`
- local caches and editor/system artifacts ignored by `.gitignore`

## 5) Manual Acceptance Expectations

- Generated review patches are not canonical automatically.
- Human review is required before accepting or promoting generated output.
- Lifecycle movement remains manual.
- Role usage remains supervised.
- Any canonical update should happen through a separate, explicit packet and review step.

## 6) Final Pre-Share Checks

```bash
git diff --check
git status --short
```

Confirm:

- only intentional files are changed
- the tracked-file-safe sanitization checks in [`docs/SANITIZATION_NOTES.md`](SANITIZATION_NOTES.md) were reviewed
- no private data leaked into tracked files
- ignored/generated evidence was reviewed separately if it is being published
- safety model language remains explicit
- onboarding docs still match actual scripts and flags
